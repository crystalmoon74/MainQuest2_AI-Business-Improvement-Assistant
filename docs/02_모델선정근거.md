# AI 모델 선정 근거

## 1. 문제의 성격
입력은 **한국어 자유 문장**, 출력은 **정해진 구조의 분석 보고서(JSON)**. 필요한 능력은
① 업무 맥락 이해와 절차 추론, ② 빠진 정보 판단과 질문 생성, ③ "입력에 있는 것 / 추론한 것"의 구분,
④ 스키마를 깨지 않는 구조화 출력이다. 이미지·음성이 아니라 **텍스트 이해·생성** 문제이므로
모듈에서 다룬 기법 중 *텍스트 생성(LLM)* 계열을 선택했다.

## 2. 후보 비교
| 후보 | 장점 | 한계 | 판단 |
|---|---|---|---|
| A. 규칙 기반(키워드 매칭) — `agent/baseline.py` | 무료·즉시·결정적 | 절차 추론·맥락 이해 불가, 동의어/다른 표현 놓침, 개선 후보 도출 불가 | **비교 기준선으로 구현** |
| B. 소형 오픈소스 LLM (Colab 로컬 실행) | 데이터 외부 전송 없음 | 한국어 업무 문맥 품질·JSON 스키마 준수가 불안정, GPU 필요, 재현 환경 구성 부담 | 보류 (사내 도입 시 재검토) |
| C. 분류 모델 파인튜닝 (문제 유형 분류 등) | 빠름 | 라벨링 데이터 없음, 질문 생성·보고서 작성은 불가 | 제외 |
| D. Claude API (claude-opus-5-5) | 한국어 장문 이해·추론 품질, 구조화 출력, PRD 권장 기술 | **유료**(학습용 PoC 예산 없음) | 선택 엔진으로 코드 유지 |
| **E. Google ADK + Gemini (gemini-3.8-flash, 무료 티어)** | **무료**, GPU 불필요, ADK `output_schema`로 구조화 출력 강제, 교육 과정에서 학습한 프레임워크(PRD 6장 언급) | 무료 한도(분당/일일 요청 수), 무료 티어는 입력이 제품 개선에 쓰일 수 있음(→ 가상 데이터만) | **채택 (기본 엔진)** |

## 3. 채택 구성과 이유
- **프레임워크/모델**: Google ADK `LlmAgent` + `gemini-3.8-flash`(무료 티어 Flash 최신). 비용 없이 누구나
  키만 발급하면 재현 가능해 과제의 "다른 사람이 실행해도 재현" 조건에 맞다. `temperature=0.2`로 결과 변동을 줄였다.
  환경변수 `GEMINI_MODEL`로 교체 가능(예: 한도 초과 시 `gemini-3.5-flash-lite`).
- **구조화 출력**: ADK `output_schema=AnalysisReport`, `output_key="report"` — Pydantic 스키마대로만 출력하고 결과를
  세션 state에 저장한다. 보고서 형식이 매번 동일하다(PRD 문제 "문서 형식과 분석 수준이 달라진다" 해결).
- **Claude 엔진(선택)**: 같은 프롬프트·스키마·가드레일로 `claude-opus-5-5`를 쓸 수 있게 남겨 두어, 예산이 생기면
  모델 간 품질 비교가 가능하다.
- **확인/추정/미확인 + 원문 인용**: 모든 사실 항목에 상태와 근거를 강제하고, 코드 가드레일이 인용문이 실제 원문에
  있는지 검사해 없으면 '추정'으로 강등한다. LLM의 환각을 **프롬프트만이 아니라 코드로도** 막는 이중 장치.
- **단일 Agent**: PRD 6장 원칙(멀티 에이전트·MCP는 필요성 확인 전 미도입)에 따라 1회 분석 호출 + 코드 검증 +
  (답변 시) 재분석 루프로 구성. ADK는 LlmAgent 1개 + InMemoryRunner만 사용하고 도구·하위 Agent는 두지 않았다.
- **안정성**: 오류 유형별(키 오류, 무료 한도 초과, 모델 없음, 서비스 장애, 네트워크) 한국어 안내와 재시도 버튼.

## 4. 기준선(A)과 비교해 확인한 점
`python eval/run_eval.py --mode demo` 결과(`eval/results/demo/`) 기준 규칙 기반의 구체적 한계:
- **업무 절차(AS-IS) 추론 0건** — 모든 사례에서 "절차 추론 불가".
- **문제점 누락** — T03의 "같은 건을 두 번 처리하거나 빠뜨리는 경우"(중복·누락 문제), T02의 핵심 문제
  "숫자가 틀리는 경우", "반나절 걸립니다"를 키워드가 없어 놓침. T02는 '개선 희망 문장'을 문제점으로 잘못 분류.
- **키워드 오탐 → 필요한 질문 생략** — T05에서 '회사'의 '회'를 빈도 정보로, '팀'을 담당자 정보로 오인해
  빈도·담당자 질문을 하지 않음. T01은 '승인'이라는 단어만으로 승인 절차가 확인됐다고 판단(단계 수·승인자는 미기재).
- **개선 후보·To-Be 생성 불가.**
Gemini 결과와의 나란한 비교는 `03_개선효과검증.md` 참고.
