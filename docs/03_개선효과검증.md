# 개선 효과 검증

> **실행 환경**: Google ADK + `gemini-3.8-flash`(무료 티어), temperature 0.2, 2026-11-17 실행.
> 재현: `python eval/run_eval.py --mode gemini` → `eval/results/gemini/` (사례별 JSON·보고서, `summary.md`).
> `[ ]` 칸은 **사람이 직접 측정해야 하는 항목**(수작업 시간, 현업/BA 피드백)이다.

## 1. 검증 방법
| 구분 | 방법 |
|---|---|
| 비교 대상 | ① **기존 방식(수작업)**: BA가 요청문을 읽고 분석 메모+질문 목록 작성 ② **규칙 기반 기준선** ③ **Gemini Agent (Google ADK)** |

## 3. 정성 비교
| 관점 | 규칙 기반 기준선 | Gemini Agent |
|---|---|---|
| **T01 업무 절차** | 추론 불가 | 요청 접수(확인) → 승인 절차(확인) → 엑셀 관리(확인) → **발주 및 결과 통보(추정)**. 입력에 없는 '발주'를 추정으로 구분함 — PRD 예시가 요구한 동작 |
| **T01 개선 후보** | 생성 불가 | 전자결재 워크플로(시스템) + **결재선·전결 규정 간소화(프로세스)** + 공유 시트 표준화. 시스템 개발만이 아닌 대안 포함 |
| **T02 문제점** | 핵심 문제 누락, 희망 문장을 문제로 오분류 | "양식이 달라 수치 오류", "취합에 반나절" 2건 모두 원문 근거와 함께 확인 |
| **T03 문제점** | 중복·누락 문제를 놓침 | 창구 다변화, 현황 미공유로 인한 중복·누락, 반복 문의 3건 모두 추출. 후보에 FAQ(교육/가이드)·셀프 비밀번호 초기화(AI 활용) 포함 |
| **T04 정보 부족** | 템플릿 질문 7개 | 업무 목적을 '추정'으로 두고 절차는 '미확인'. 품목 종류, 관리 도구, 가장 불편한 작업 등 **재고 업무 맥락에 맞춘 질문 9개** |
| **T05 목적 불명확** | 문제점 0건 | 'AI 챗봇 도입'을 결론으로 확정하지 않음. 문제점은 '미확인'으로 두고 첫 질문으로 "가장 크게 느끼는 불편함/개선 이유"를 물음. 후보도 FAQ 정비를 먼저 제시 |

## 4. 실패 사례 / 사실 확정 오류 기록
| 사례 | 현상 | 원인 추정 | 대응 |
|---|---|---|---|
| **Gemini T01** | 문제점 "승인 과정이 복잡하여 **결재 지연 및 업무 혼선**이 발생함"을 '확인'으로 표시. 인용 근거("승인 과정이 복잡하고")는 원문에 있으나 '결재 지연·업무 혼선'은 입력에 없음 | 모델이 내용을 그럴듯하게 덧붙임. 가드레일은 **인용문 존재만** 검사해 탐지 못함 | 한계로 기록. 다음 단계: 내용(content)과 인용문의 의미 일치를 검사하는 2차 검증 |
| **Gemini T05** | 문제점 "현행 프로세스의 비효율 요인이 확인되지 않습니다"를 '확인'으로 표시 | '정보가 없다는 사실'을 확인으로 분류한 상태 오용 | 프롬프트에 "정보 부재는 미확인으로" 규칙 추가 검토 |
| Gemini T01·T02 | 이미 아는 시스템(이메일·엑셀) 관련 질문을 '기타' 범주나 세부 질문(M365 사용 여부)으로 다시 물음 | 범주 필터는 '기타'를 예외로 둠 | 대부분 추가 정보를 묻는 유효한 질문이라 허용. 중복 여부는 사람이 판단 |
| 운영 | 첫 일괄 실행에서 5건 중 3건이 503(과부하) | 무료 티어 서버 혼잡 | 5초·15초 대기 후 자동 재시도 추가 → 전부 성공 |
| 기준선 T05 | '회사'의 '회'를 처리 빈도로 오인 → 빈도 질문 생략 | 단순 부분 문자열 매칭 | LLM 채택 근거 |
| 기준선 T02 | 핵심 문제(숫자 오류, 반나절 소요) 미검출 | 키워드 사전 한계 | LLM 채택 근거 |

## 5. 결론
- **달성**: 5개 사례 모두 60초 이내에 구조화된 보고서를 만들었고, 질문 규칙(≤10, 중복 0)을 지켰다. 정보가 부족하거나
  목적이 불명확한 요청(T04·T05)에서 결론을 확정하지 않고 질문 위주로 대응했다. 규칙 기반으로는 불가능했던
  절차 추론·개선 후보·To-Be 초안을 얻었다.
- **한계**: 사람 검토에서 사실 확정 오류 2건을 찾았다. 가드레일은 인용문 존재만 보므로 내용 과장은 잡지 못한다.
  AI 결과는 반드시 사람이 검토해야 한다는 PRD 원칙이 실제로 필요함을 확인했다.
- **남은 측정**: 수작업 대비 시간(S3)과 현업/BA 피드백(S8)은 사람이 직접 측정해 2-4와 2-3에 기입한다.
