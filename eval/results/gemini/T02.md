## 1. 업무 개요
매주 월요일 5개 지역 영업 담당자의 엑셀 파일을 수작업으로 취합하여 주간 실적 보고서를 작성하고 팀장에게 메일로 보고하는 업무입니다. 파일별 양식 불일치로 인한 복사·붙여넣기 오류와 반나절에 달하는 취합 소요 시간을 개선하고자 합니다.

**업무 목적**: ✅ 확인 지역별 영업 실적을 취합하여 주간 단위 실적 보고서를 작성하고 팀장에게 보고한다.

## 2. 현재 업무 방식 (AS-IS)
매주 월요일 지역 영업 담당자 5명이 각각 작성한 엑셀 파일을 전달받아, 담당자가 수작업으로 복사·붙여넣기하여 하나의 보고서로 취합합니다. 이후 완성된 최종 보고서를 팀장에게 이메일로 발송하여 보고합니다.

| 2 | 데이터 복사 및 보고서 취합 | ✅ 확인 | 파일마다 양식이 조금씩 달라서 복사·붙여넣기를 하다 보면 |

## 6. 개선 후보 (검토 후보)
### 후보 1. 표준 엑셀 템플릿 배포 및 입력 규칙 통일 `프로세스 개선`
지역별 담당자 5명이 공통으로 사용할 표준 양식을 정의하고, 셀 서식 및 필수 입력 항목을 고정하여 배포

- 해결 대상 문제: 파일마다 양식이 조금씩 달라서 발생하는 수작업 취합 번거로움
- 기대 효과: 양식 통일만으로도 취합 공수 감소 및 단순 오기 방지
- 검토 전 전제 조건: 5개 지역 담당자의 동의 및 표준 양식에 맞춘 작성 협조 가능 여부

### 후보 2. 공동 편집 스프레드시트(구글 시트/M365 엑셀) 도입 `시스템/자동화`
클라우드 기반 단일 시트에서 5개 지역 담당자가 각자 영역에 직접 입력하도록 하여 파일 취합 단계 자체를 제거

- 해결 대상 문제: 5개 파일을 각각 받아 수작업으로 복사·붙여넣기하는 프로세스
- 기대 효과: 별도 파일 합치기 작업이 사라져 취합 시간 '0'에 수렴
- 검토 전 전제 조건: 사내 보안 정책상 클라우드 기반 공동 작업 도구 사용 허용 여부

### 후보 3. 엑셀 매크로(VBA) 또는 파이썬 기반 자동 취합 도구 개발 `시스템/자동화`
폴더 내 5개 엑셀 파일을 읽어와 지정된 규칙에 따라 자동 병합 및 합계 검증을 수행하는 스크립트 제공

- 해결 대상 문제: 복사·붙여넣기 시 발생하는 숫자 오류 및 반나절의 취합 소요 시간
- 기대 효과: 버튼 클릭 또는 스크립트 실행으로 수 분 내 취합 완료 및 오류 배제
- 검토 전 전제 조건: 기초 데이터 항목의 규격화 선행 및 담당자 PC 환경 내 스크립트/매크로 실행 권한

1. **[사용 중인 시스템]** 사내에서 Microsoft 365(OneDrive/SharePoint)나 구글 워크스페이스 같은 온라인 공동 편집 도구를 공식적으로 지원하고 있나요?  
   └ 필요한 이유: 단일 온라인 파일 공동 작성 방식으로 파일 취합 과정 자체를 제거할 수 있는지 확인하기 위함
2. **[사용 중인 시스템]** 현재 영업 실적 데이터는 ERP나 CRM 등 별도 시스템에서 내려받는 데이터인가요, 아니면 담당자가 직접 수기로 집계하는 데이터인가요?  
   └ 필요한 이유: 원천 시스템이 있다면 시스템 리포트 직접 추출이나 연동을 통한 개선 가능성을 검토하기 위함
3. **[예외 처리]** 월요일 보고 기한까지 5명 중 일부가 파일을 늦게 보내거나 누락하는 경우가 발생하나요? 발생한다면 어떻게 처리하시나요?  
   └ 필요한 이유: 미제출자 발생 시 취합 지연 문제 및 예외 알림/프로세스 정의가 필요한지 파악하기 위함
4. **[예외 처리]** 보고서 취합 후 숫자가 맞는지 확인하는 별도의 검증 절차나 수식(합계 검산 등)이 기존에 마련되어 있나요?  
   └ 필요한 이유: 자동 취합 시 포함해야 할 유효성 검사 규칙(Validation Rule)을 도출하기 위함
5. **[승인 절차]** 팀장님 메일 보고 시 단순 실적 수치 공유 외에 결재·승인 등의 공식 결재선이나 피드백 절차가 수반되나요?  
   └ 필요한 이유: 단순 보고 프로세스인지, 전자결재나 확인 이력 관리가 필요한 업무인지 확인하기 위함
6. **[기대 효과]** 취합 시간(현재 반나절)이 단축될 경우, 목표로 하는 허용 시간(예: 30분 이내)이나 절감된 시간에 수행하고자 하는 주요 업무는 무엇인가요?  
   └ 필요한 이유: 프로젝트 목표치(KPI)를 구체화하고 개선 효과의 정량적 타당성을 검증하기 위함
